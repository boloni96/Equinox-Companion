# Companion 0.5.1.54 — local FollowThem and coffer markers

Settings now has a Features tab for QuickLoot, FollowThem and Treasure Coffer markers. Existing QuickLoot rules and enable preference remain intact. The two new features are independently disabled by default and do not enter the Journal sync payload.

FollowThem chooses a current party member or cached friend by exact name and home world. Its top-bar entry starts/stops the session and shows STOPPED, WAITING, LOADING or the selected name. Resume-nearby is optional; explicit Stop cancels waiting. Logout/character changes, manual movement, combat, incapacitation and cutscenes stop the session. Movement uses vanilla /follow with no vnavmesh dependency. It does not mount, fly or avoid obstacles automatically.

Party teleport acceptance is separately opt-in, gated by an active native teleport request, a party and an open English "Accept Teleport to ...?" prompt. Minimized notifications and other languages are not automatically accepted in this version.

Experimental portal relay requires Journal V7.11.74. The leader enables Share my portal transitions; the follower enables Use shared portal, selects that character and starts FollowThem with resume-nearby enabled. Both use the same pairing key. There is no manual portal registration. A native Warp/Exit portal click is retained for at most ten seconds; only a subsequent area transition or large position jump sends the instruction. Cancelling without transitioning sends nothing. A separate authenticated endpoint expires instructions after 15 seconds; no Journal save, revision, event or live-roster update is created. Sender settings and movement state are not shared.

The follower requires an exact selected name/home world, matching current world/map, a matching recently observed player entity (same instance evidence), a fresh instruction after Start, and a matching native portal within three yalms. Each instruction is attempted once. The exact same supported English confirmation can be accepted; paid prompts, unrelated dialogs, destination lists and unsupported handler types are not automated. Reads happen at most once per second while armed with this option enabled and a recent nearby leader; failures back off. Normal follow needs no relay. No message is queued to replay after reconnect.

Coffers are read twice per second while enabled. Native Opened flags or an exact loot-window chest identity confirm green; disappearing or non-targetable objects alone do not. Opened locations survive disappearance for this map/territory visit. Logout, territory/map changes and manual clear remove history. A bounded cache and native minimap layout provide local markers, without an estimated screen projection, Journal writes or auto-opening. Special coffers implemented as Event Objects are not supported yet. At most 32 nearby markers are appended and 100 locations retained. Existing native markers are not overwritten.

Validation: Release build, zero warnings/errors; 919 automated checks pass (53 added), plus relay API and existing cloud/companion regression checks. These verify policy, identity, stop/wait/loading transitions, strict prompt matching, coffer retention/ID reuse and unchanged-data behavior. Source/build checks are not in-game validation. Vanilla follow cancellation, actual command success, portal interactions, native minimap hook/layout/rotation/zoom and real FPS must be verified in game. New feature tests 251–263 in the shared checklist are deliberately unmarked.

Deploy Journal V7.11.74 to the same Cloudflare project to enable portal relay. Existing Journal data and other Companion features remain compatible. Cloudflare deployment is performed by the owner.
